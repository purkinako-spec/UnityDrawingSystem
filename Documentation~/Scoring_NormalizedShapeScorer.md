# 開発・設計メモ：位置・スケール不変採点エンジン (NormalizedShapeScorer)

## 1. 概要
見本画像がキャンバス全体にあり、ユーザーが画面端（例：右下）に小さく描画した場合でも、形状が一致していれば適切に高得点を算出できる位置・スケール不変（Translation & Scale Invariant）採点エンジンです。

---

## 2. システムに干渉しない設計上の配慮（既存破壊防止）
本機能の実装において、既存システムへの影響をゼロにするため以下のルールを徹底しています。

1. **既存コードへの非侵襲（ゼロ・モディフィケーション）**:
   - `DrawingCanvas.cs`、`BrushEngine.cs`、既存の `ShapeScorer.cs`、`PixelSimilarityScorer.cs` などのコアスクリプトには一切変更を加えていません。
   - `IScoringEngine` インターフェースを満たす独立した ScriptableObject（`NormalizedShapeScorer`）として追加したため、プラグインのようにアセット選択だけで安全に切り替え・併用が可能です。

2. **メタデータ（.meta）の完全整合**:
   - Unity Package Manager (UPM) や Git でアセット管理エラーを起こさないよう、Unity標準のGUIDを含む `.meta` ファイルを正しく生成しています。

3. **メモリとGC配慮**:
   - 採点時の正規化解像度（デフォルト 256x256）は固定で管理され、不要な RenderTexture やテクスチャリークを発生させない安全な設計にしています。

---

## 3. 実装した「こだわりのアルゴリズム」

### ① 孤立微小点（ゴミ・かすり傷）のフィルタリング（Connected Component Analysis）
- **課題**: 画面端にうっかり触れてできた1ドット〜数ドットの微小な点があると、単純な最小・最大値（Min/Max）では外接矩形がキャンバス全体に広がってしまい、スケール補正が破綻します。
- **解決策**:
  - 描画ピクセルの連結成分（塊）を幅優先探索（BFS）で探索。
  - `minComponentPixelCount`（デフォルト 15ピクセル）未満の極小孤立成分を「ノイズ」として除外したクリーンマスクを生成してから矩形を計算します。

### ② パーセンタイルによる外れ値カット（Outlier Trimming）
- **解決策**:
  - ノイズ除去後に残ったピクセルの座標分布に対し、上下左右の `outlierPercentile`（外側2%）をカットして真の描画主領域（Bounding Box）を特定します。

### ③ アスペクト比維持のセンタリング正規化
- **解決策**:
  - 縦横比を無理に引き延ばすと円が楕円になってしまうため、元の絵の縦横比を完全に維持したまま、周囲に適度なパディング（`paddingRatio` = 5%）を設けて正方形（256x256）の中央に綺麗に配置します。

### ④ 形状（IoU）と密度差分による高精度スコアリング
- **解決策**:
  - 見本と描画の両方を同じルールで中央正規化し、重なり率（IoU 70%）と密度一致率（Density 30%）をブレンドしてスコアを算出します。
  - ヒートマップも出力され、緑＝一致、赤＝余計な線、青＝不足している線として可視化されます。
